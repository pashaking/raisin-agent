Scenario

Flows

Request path

Browser → raisin-api (JWT from /auth/token) → agent-runtime → litellm → provider. Donations go raisin-api → payment-gateway and never touch the AI path.

Control checks per request

OPA model stage (allowed model, tools, retrieval filter), Presidio analyze, guardrails input check, one NeMo self-check per retrieved chunk, OPA tool stage per call, guardrails output check, Presidio anonymize for Donors. Any control unreachable means deny.

Shared Postgres, three databases

raisin (donations, transactions, donors, registry table), kb (pgvector docs, agent_memory, approvals), litellm (virtual keys, spend). Single poc role, no RLS (open finding F4).

Observability

Collector drops raw gateway spans and strips message content, then exports to Jaeger (gRPC), Phoenix (HTTP) and observability/siem/security-events.jsonl for spans tagged as security events. OPA sends its own traces too.

One-shot jobs

seed (profile seed): schema, fixtures, LiteLLM virtual keys, embeds 10 docs through the gateway, PUTs the registry into OPA. gate (profile gate): hour-one trace-nesting risk gate against LiteLLM.

Not drawn

Responses for seed, gate and traces (fire-and-forget or setup-only). Host port offsets (14xxx / 15xxx / 16xxx / 18xxx), health checks, the guardrails classifier download at first start, and the roles.json mount that raisin-api also reads.
