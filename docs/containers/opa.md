# opa

Open Policy Agent, the **Policy Decision Point**. Two Rego packages: `aicp.authz` decides what the assistant may do;
`system.authz` decides who may talk to OPA itself. Data comes from a static `roles.json` and a generated `registry.json`
that `seed` pushes at runtime. The runtime enforces the decisions and fails closed if OPA is unreachable.

| | |
|---|---|
| Image | `openpolicyagent/opa:1.20.2` |
| Port | none on the host (security review F3). Query via `make opa-query INPUT='...'` (runs inside `agent-runtime` with its token) or `make opa-data PATH=...` (inside `seed`) |
| Command | `opa run --server --addr :8181 --authentication=token --authorization=basic --config-file /config/opa-config.yaml /policies /data /opa-tokens/tokens.json` |
| Mounts | `policy/authz.rego`, `policy/system_authz.rego` (read-only), `policy/opa-config.yaml`, `policy/data/` (`roles.json`, `registry.json`), compose config `opa_tokens` rendered from `.env` (`OPA_TOKEN_RUNTIME`, `OPA_TOKEN_SEED`) |
| Tracing | `distributed_tracing: grpc otel-collector:4317`, 100 % sampled; `decision_logs.console: true` |
| Tests | `make opa-test`: 39 cases in `authz_test.rego` + `system_authz_test.rego` |

## Inputs

`data.roles` (`policy/data/roles.json`):

| Role | Models | Tools | Retrieval classifications |
|---|---|---|---|
| Finance | `claude-sonnet`, `gpt-4o-mini` | `get_transaction_analysis`, `get_donation`, `list_transactions`, `get_tenant_donation_summary`, `get_donor_profile`, `find_donor`, `search_kb`, `get_user_context`, `get_session_context`, `save_task_state`, `resend_receipt`, plus the Phase 3 investigation set and the Phase 14 controlled-action set (see [agent-runtime.md](agent-runtime.md#tool-layer-toolspy)) | `platform`, `tenant-internal` |
| Donor | `gpt-4o-mini` | `search_kb`, `get_my_donations`, `get_user_context`, `get_session_context`, `save_task_state` | `platform` |
| Participant | `claude-sonnet`, `gpt-4o-mini` | none | none |

`data.registry` (`policy/data/registry.json`, generated by `seed registry` from `ai_registry`): `models`, `tools`, `prompts`,
each `{owner, risk_tier, approved, version}` (tools also carry `action_risk`), plus `revision` (sha256 prefix of the
document). Currently 3 models, 30 tools (`legacy_summarizer` unapproved; `resend_receipt` approved and in Finance's
role list, but still always denied at the tool stage with `requires_approval` — see
[Risk classification](#risk-classification)), 2 prompts.

## Decision contract (`POST /v1/data/aicp/authz/decision`)

Input:

```json
{"input": {"stage": "model" | "tool",
           "subject": {"sub": "...", "tenant_id": "tenant-a", "role": "Finance"},
           "model": "gpt-4o-mini",            // model stage, optional ("" = role default = first in list)
           "prompt": "assistant-system-v1",   // model stage
           "tool": "get_donation",            // tool stage
           "resource": {"tenant_id": "tenant-a"}}}   // tool stage
```

Model stage allows when the requested model is in the role's list **and** approved in the registry **and** the prompt is
approved. Output on allow:

```json
{"allow": true, "stage": "model", "model": "gpt-4o-mini",
 "allowed_tools": ["...role tools that are approved..."],
 "withheld_tools": ["...approved tools not in the role..."],
 "retrieval_filter": {"tenants": ["tenant-a", "platform"], "classifications": ["platform", "tenant-internal"]},
 "reason": "ok", "registry_revision": "b6d21bfcf80e4165"}
```

Deny reasons, in evaluation order: `unknown_role`, `model_not_in_role`, `unapproved_model`, `unapproved_prompt`, `denied`.

Tool stage allows when the tool is in the role **and** approved **and** `resource.tenant_id == subject.tenant_id` **and**
its `action_risk` is not `high`/`critical`. Every tool-stage decision (allow or deny) also carries `"risk"`
(`low`\|`medium`\|`high`\|`critical`\|`unknown`). Deny reasons, in evaluation order: `unknown_role`, `tool_not_in_role`,
`unapproved_tool`, `tenant_mismatch`, `requires_approval`, `denied`.

**`approval_execute` stage** (Phase 10): the only call that can allow a `high`/`critical` tool, and only the agent
runtime's `/approvals/{id}/decide` endpoint ever sends it — never the agent's own tool-call loop. Same input shape as
`tool`, `stage: "approval_execute"`:

```json
{"input": {"stage": "approval_execute", "subject": {"sub": "...", "tenant_id": "tenant-a", "role": "Finance"},
           "tool": "resend_receipt", "resource": {"tenant_id": "tenant-a"}}}
```

Allows when the tool is in the role **and** approved **and** `resource.tenant_id == subject.tenant_id` **and** —
the mirror image of the `tool` stage — its `action_risk` **is** `high`/`critical` (`requires_approval` must be true;
this stage refuses to be used on a tool that was never gated by approval in the first place). Deny reasons, in
evaluation order: `unknown_role`, `tool_not_in_role`, `unapproved_tool`, `tenant_mismatch`, `not_requires_approval`,
`denied`.

Every response carries OPA's `decision_id`, which the runtime copies onto the span and OPA writes to its console decision log.

## Risk classification

Phase 9: every tool in the registry carries `action_risk`. `low` and `medium` execute automatically once role,
approval and tenant checks pass; `high` and `critical` always deny at the `tool` stage with `requires_approval` —
that stage never grants them, by design. Phase 10 adds the separate `approval_execute` stage above: the agent
runtime creates a pending approval request on the `requires_approval` deny (see
[agent-runtime.md](agent-runtime.md#human-approval-workflow-approvalspy-phase-10)), a human decides, and only an
approve re-asks OPA through `approval_execute` before anything runs. `resend_receipt` is the one `high` tool today,
now in Finance's role list specifically so this path is reachable for real, not dead code.

| Tool | action_risk | Why |
|---|---|---|
| `get_transaction_analysis`, `get_donation`, `list_transactions`, `get_tenant_donation_summary`, `get_my_donations`, `search_kb`, `get_user_context`, `get_session_context` | low | read-only, already tenant-scoped and field-minimized |
| `get_donor_profile`, `find_donor` | medium | identify one donor, even though returned fields are minimized |
| `save_task_state` | medium | a write, even though fully self-scoped (own tenant/user/session) with no external side effect |
| `get_campaign`, `get_campaign_statistics`, `get_transaction`, `search_transactions`, `get_transaction_statistics`, `compare_transaction_periods`, `get_decline_statistics`, `get_payment_gateway_statistics`, `get_fraud_signals`, `get_application_errors`, `get_incident_history` | low | read-only (Phase 3 investigation set) |
| `create_incident`, `send_notification`, `collect_diagnostic_bundle` | low | scoped to the caller's own charity; no backing system in this POC (Phase 14) |
| `restart_worker`, `clear_failed_job`, `block_ip_temporarily` | medium | a real, scoped, reversible/time-bounded side effect, same tier as `save_task_state` (Phase 14) |
| `resend_receipt` | high | a real side effect (not a read); gated by approval, not withheld outright |

`tenant_mismatch` is still checked before `requires_approval` (and, at the `approval_execute` stage, before
`not_requires_approval`): a cross-tenant request always reads as `tenant_mismatch` — the access-control boundary
always outranks the autonomy gate.

## OPA's own API (`system.authz`)

| Identity (bearer token) | Allowed |
|---|---|
| anyone | `GET /health` |
| `runtime` token | `POST /v1/data/aicp/authz/decision` only |
| `seed` token | `PUT /v1/data/registry`; `GET /v1/data/**` |
| anything else, or a policy upload | denied |

So a compromised container on the compose network cannot rewrite the policy or read roles without one of the two tokens,
and the runtime's token cannot change anything.

## When it is down

Every `policy.decide` times out (2 s) or fails to connect; the runtime synthesizes `{allow: false, reason: unavailable}`,
records the exception on the span, and returns 403 `policy_deny`. No model or guardrail call is made. `raisin-api`'s
`/api/*` role check does not depend on OPA (it reads `roles.json` directly), so an OPA outage does not open the backend.

Note: `roles.json` is read at OPA start; edit it and `docker compose restart opa`. `registry.json` is pushed live by `seed`.

## Success example

Model stage for the Donor persona (`make opa-query`):

```json
{"decision_id": "4b0f7936-59ae-4bf6-929e-f0d2115e7c08",
 "result": {"allow": true, "stage": "model", "model": "gpt-4o-mini", "reason": "ok", "registry_revision": "4b3476057f886118",
            "allowed_tools": ["search_kb", "get_my_donations", "get_user_context", "get_session_context", "save_task_state"],
            "withheld_tools": ["find_donor", "get_donation", "get_donor_profile", "get_tenant_donation_summary", "get_transaction_analysis", "list_transactions", "resend_receipt"],
            "retrieval_filter": {"tenants": ["tenant-b", "platform"], "classifications": ["platform"]}}}
```

The runtime turned this into two tool schemas and a `WHERE tenant_id IN ('tenant-b','platform') AND classification IN ('platform')`.

`approval_execute` allow (Phase 10), Finance A deciding their own tenant's pending `resend_receipt` request:

```json
{"decision_id": "9003f45b-bf97-4422-ac16-0639657f951a",
 "result": {"allow": true, "stage": "approval_execute", "tool": "resend_receipt", "risk": "high", "reason": "ok",
            "registry_revision": "4b3476057f886118"}}
```

## Failure examples

Tool stage, Finance B on tenant A's donation (F6):

```json
{"decision_id": "994d0a1a-6de1-43c5-83a3-0ed8d8b8d9b0",
 "result": {"allow": false, "reason": "tenant_mismatch", "risk": "low", "registry_revision": "b6d21bfcf80e4165", "stage": "tool", "tool": "get_donation"}}
```

Model stage, Finance asks for `gpt-4o` (F2):

```json
{"decision_id": "32cbe850-ad3b-4023-ae59-ba9a4eca52b2",
 "result": {"allow": false, "reason": "model_not_in_role", "registry_revision": "b6d21bfcf80e4165", "stage": "model"}}
```

Registry flip (S6): `make registry-flip TOOL=get_donation APPROVED=false` → next model-stage decision has `get_donation`
missing from `allowed_tools` and a new `registry_revision`; a tool-stage call for it would deny with `unapproved_tool`.
